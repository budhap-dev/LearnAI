## The one idea

**An open-weight model is one whose weights you can download and run yourself.** That is a
different thing from "open source" and from "unrestricted" — it means you hold the weights and
can serve them on your own hardware. Doing so buys three things a hosted API structurally
cannot: **data never leaves your machine**, there is **no per-token bill**, and **nothing breaks
when a vendor deprecates a model.** The costs are the ones the API was hiding for you — the
hardware, the quantisation trade-off, and the licence.

The whole course records against a local model (served by Ollama), through the *same adapter*
as every hosted call in Module 5. Only the endpoint is local:

```code
run-local
```

```output
run
```

No API key was read and no request left the host — the exact same `complete()` you've used all
course, pointed at a model running on your own machine.

## Quantisation: the size/quality dial

The first number that decides whether local is feasible is memory, and the lever for memory is
**quantisation** — how many bits you store each weight in. Fewer bits, smaller footprint, at
some quality cost:

```code
quantise
```

```output
size
```

```diagram
quantisation-tradeoff
```

The pattern is the point. **fp16** is the usual server default. **int8** roughly halves the
memory for a negligible quality loss. **int4** quarters it for a modest one — and that is what
lets an 8B model fit on a single consumer GPU. The rule of thumb worth memorising:
**int4 ≈ params/2 in GB**, so an 8B model in 4-bit is about 4 GB of weights. Quality falls
slowly as you drop bits, then faster below 4-bit — which is why int4 is the common floor.

```check
You want to run an 8-billion-parameter model on a single 16GB GPU with room for the KV cache and activations. Which quantisation is the sensible default?
- fp16 — it's the server standard
- * int4 (~4GB of weights) or int8 (~8GB) — both leave headroom on a 16GB card, whereas fp16 (~16GB) fills it with weights alone and leaves nothing for the KV cache
- fp32 — highest quality
why: fp16 weights for 8B are ~16GB, which alone fills a 16GB card with no room for the KV cache and activations. int8 (~8GB) or int4 (~4GB) leave headroom, and the quality loss — negligible at int8, modest at int4 — is the price of fitting.
```

## When local is worth it — and when it is not

```output
worth
```

Neither answer is universal; it is a genuine trade:

- **Local wins** when data cannot leave (privacy, regulation, air-gap), when volume is high and
  steady so there's no per-token bill on a busy path, or when you need predictable latency and
  offline operation.
- **Hosted wins** when you want the frontier model, when volume is spiky or low (pay only for
  what you use), when you have no team to run GPUs, or when you need the newest model the day it
  ships.

The honest cost of local is **not $0** — it is the GPU, the quantisation tuning, and the
on-call to keep it serving. "Free" refers to the per-token bill, not the total cost of
ownership.

## The licence is not an afterthought

```output
licence
```

"Open weights" is a spectrum of licences, not one, and the differences decide what you may ship:

- **Apache-2.0 / MIT** — the permissive default: use commercially, modify, redistribute.
- **Community licences** (e.g. Llama's) — permissive *until* you cross a large-user threshold,
  then you must negotiate.
- **Use-policy licences** (e.g. Gemma's terms) — commercial use is fine, but there's an
  acceptable-use policy you must pass through to your users.
- **Research-only** — evaluation or non-commercial use; **not** for production, and a common,
  costly trap.

**Open weights ≠ open source ≠ unrestricted.** Read the licence before you build on a model, the
same way you would for any dependency — because the licence, not the download button, decides
what you're allowed to do.

```check
A model card says the weights are "available for research and evaluation." Your team wants to serve it in a paid product. What is the correct read?
- It's open weights, so commercial use is fine
- * "Research and evaluation" is a research-only licence — it does not permit production/commercial use. Using it in a paid product would breach the licence; pick a permissively-licensed model (Apache-2.0/MIT) or one whose terms allow commercial use
- Licences don't apply once you download the weights
why: "Open weights" is not "unrestricted." A research/evaluation licence forbids commercial deployment. You must choose a model whose licence permits your use — downloading the weights does not grant rights the licence withholds.
```

## What a senior engineer should take from this

- **Open-weight = you hold and run the weights**: data stays put, no per-token bill, no vendor
  deprecation — and you own the hardware and ops in exchange.
- **Quantisation is the size/quality dial**: int8 ≈ half the memory for ~no loss, int4 ≈ a
  quarter for a modest loss (int4 ≈ params/2 in GB).
- **Local vs hosted is a real trade** — privacy/volume/latency vs frontier quality/spiky
  volume/no ops — and local's cost is the GPU and on-call, not zero.
- **The licence decides what you may ship**; "open weights" ranges from Apache-2.0 to
  research-only, so read it like any dependency.

## Model answers (sketch)

1. fp16: `70e9 × 2 / 1024³ ≈ 130 GB` (multi-GPU or a big datacentre card). int4:
   `70e9 × 0.5 / 1024³ ≈ 33 GB` (one 40–48GB card, weights-only). The KV cache grows with
   context length and batch and eats into the headroom, so budget above the weights figure.
2. Usually: does data have to stay in-house (→ local), is volume high and steady (→ local) or
   spiky (→ hosted), do we need the frontier model (→ hosted). Name which dominates.
3. Apache-2.0/MIT → fine for a paid product; community licences → fine below the user threshold,
   check it; research-only → avoid for production. Avoid anything whose licence forbids
   commercial use however good the weights are.
4. Serving infra and autoscaling, GPU/driver failures, model and runtime upgrades, quantisation
   regressions, capacity for spikes, and monitoring/latency SLOs — all of which a hosted API
   operates for you.
