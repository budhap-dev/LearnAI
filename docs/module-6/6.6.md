## The one idea

A model with the right passages in front of it can still answer from memory, blend in a
plausible detail, or round a number. **Grounding** is the set of rules and checks that make the
answer come *from* the passages and make that checkable:

```diagram
grounded-vs-ungrounded
```

Three parts, all needed: a prompt that demands citations and allows refusal; code that verifies
the citations; and a routing decision — serve, review, or escalate — based on what the code
found.

## The grounding prompt

```code
prompt
```

Four rules, each doing a job. *Only the provided articles* scopes the model. *Every factual
sentence ends with an id* makes each claim traceable. *NOT_COVERED* gives the model a
first-class way to say no (Lesson 2.6: without it, the model will be helpful with facts it
does not have). *Be brief* limits the surface for invention. The passages carry ids in square
brackets so the model has something concrete to cite.

## Verify in code

```code
verify
```

Code checks what the model claimed, using nothing but the passages it was given:

- every cited id names a passage that was **actually provided** (not one the model remembered
  from training, not a typo);
- every factual sentence **carries a citation**;
- every **number** in a sentence appears in the text of a passage that sentence cites — the
  cheapest faithfulness check there is, and it catches the commonest invention: a plausible
  figure.

None of this proves the answer is right. All of it proves the answer is *traceable*, which is
what lets a human check quickly and what stops the invented-policy incident from Lesson 1.6.

```check
The model's answer cites [billing] — but retrieval provided [refunds], [seats] and [plans]. What happened, and what should code do?
- The model found a better source
- * It cited something it was not given (memory or invention); code flags the answer for review rather than serving it
- Nothing — citations are decorative
why: A citation to a passage that was not in the prompt cannot be checked; treat it as ungrounded. This is exactly the case the id check exists for.
```

## Three questions, three routes

```output
q-how
```

Two claims, two citations to the retention article, numbers present in it, nothing uncited:
**serve**, and render the citations as links so the user can check.

```output
q-what
```

A single cited sentence, the number ("four hours") in the support article: **serve**. Notice
that two of the three retrieved passages were irrelevant; the model ignored them, as the
grounding prompt told it to.

```output
q-do
```

Retrieval returned the three least-bad articles; the model — scoped to them — said
`NOT_COVERED`. **Escalate to a human.** This is the behaviour the whole module is protecting:
the system can say no, and your code can tell that it did.

```check
A grounded answer passes every code check: ids exist, every sentence cited, numbers present. Is it correct?
- Yes — it passed verification
- * It is traceable, not proven: the checks catch invention and mis-citation; correctness still needs the golden-set eval (6.7) and, where it matters, a human
- No — code checks are useless
why: Verification makes answers checkable and blocks the common failures. It does not replace evaluation on real questions.
```

## Rendering and routing

```output
why
```

- **Render citations as links** to the source passage. Users check, trust rises, and you get a
  free signal about which articles answer which questions (and which questions have no
  article — content to write).
- **Route by the checks**: clean → serve; any unknown id, uncited claim or number not in the
  source → review queue; `NOT_COVERED` → human, and log it as a coverage gap.
- **Add a faithfulness judge** (Lesson 6.7) for the claims code cannot check — paraphrased
  facts, policy statements — and spot-check the judge.
- **Keep the refusal honest**: if the model refuses questions the corpus *does* cover, users
  stop trusting it; measure refusal precision (6.7), and tune the rule, the retrieval, or
  the threshold.

## What a senior engineer should take from this

- **Ids in, citations out, refusal allowed** — the prompt that makes grounding possible.
- **Verify citations in code**: ids exist, claims cited, numbers in the source. Traceable is
  not proven, but it blocks the invented-policy class of incident.
- **Route on the checks**: serve / review / escalate. Render citations as links.
- **The refusal path is the feature.** Measure that it fires exactly when it should.

## Model answers (sketch)

1. Catches paraphrased claims with no support; false positives on legitimate rephrasing —
   tune the overlap length, or use a judge for those.
2. Typically it answers anyway with a plausible policy — the invented-discount incident.
3. The question, the passages, the answer with citations highlighted, the failed check;
   actions: approve, edit, escalate, "no article covers this"; approved/edited pairs become
   golden cases.
4. Retrieval missing the passage (hit@k), a threshold set too high (coverage vs score),
   the prompt over-refusing (refusal precision on the golden set).
