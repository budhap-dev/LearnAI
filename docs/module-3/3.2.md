## The one idea

Strip the vocabulary and a classic model is small: **a function from a row of numbers
(features) to a score, whose parameters were chosen to fit labelled examples.** Regression
predicts a number (a price, a delay); classification predicts a category, usually via a
score you threshold. Everything else — trees, boosting, neural nets — is a different family
of function fitted by the same loop from Lesson 1.2.

## Build two of them

The dataset: service instances described by two numbers, labelled healthy or not:

```code
data
```

### Features first

```code
features
```

Models are fitted to numbers, so before any model comes **feature preparation**: scale
columns to comparable ranges, encode categories as numbers, derive useful transforms
(log of money, hour of day). Two rules that cause most production bugs when broken:

- **The exact same feature code runs at training and at serving.** One function, called from
  both places (Lesson 3.5).
- **Fit any statistics (means, scales, vocabularies) on training data only**, then apply
  them to everything else. Fitting them on the data you are predicting leaks the answer.

### Logistic regression — the workhorse

```code
logistic
```

A weighted sum of the features, squashed into (0, 1). Trained by gradient descent on log-loss —
the same nudge-against-the-gradient loop as Lesson 1.2, with a loss that punishes confident
wrong probabilities:

```output
logistic
```

The weights *are* the explanation: error rate matters about twice as much as request rate
here, and both push toward "unhealthy". That legibility is why logistic regression is the
first thing to try and often the last thing you need — and why regulated decisions favour it.

```check
Logistic regression gave a row p = 0.72. What does that number mean, on its own?
- The row is unhealthy
- * A score you can read as a probability — it becomes a decision only when you compare it with a threshold
- The model is 72% accurate
why: A score is not a decision. Which threshold to apply is decided by the cost of each kind of error (Lesson 3.3), not by the model.
```

### From score to decision: the threshold

```output
threshold
```

Nothing in the model chooses 0.5. Lower thresholds catch more (higher recall) at the price of
false alarms; higher thresholds are precise but miss cases. Lesson 3.3 is about choosing on
purpose.

### A decision tree — one question at a time

```code
stump
```

```output
stump
```

A tree asks a question about one feature, then another about the answer, and so on; a
**stump** is one question. Trees handle non-linear boundaries and mixed feature types
without scaling, and they are easy to read. Alone they overfit; **gradient boosting** fixes
that by fitting hundreds or thousands of small trees in sequence, each correcting the
residual errors of the ones before. Boosted trees are the strongest default on tabular data
and what most production "classic ML" is — the mechanism is exactly this stump, repeated.

### Inference on rows the model never saw

```output
new-rows
```

Both models answer for `(500, 0.3)` — a row unlike anything in training. Neither says
"I have no idea". That is the same lesson as 2.8 in a different costume: **a model produces
outputs; your evaluation and your monitoring decide whether to believe them.**

```check
You must predict next month's spend per customer (a number, not a category). What is that task called and what changes?
- Classification; use logistic regression
- * Regression; the model outputs a number and the loss is on the size of the error, not on a probability
- Clustering; group customers by spend
why: Predicting a quantity is regression — linear models, trees and boosting all have regression forms; evaluation uses error size (MAE, RMSE) instead of precision/recall.
```

## The families, and what to reach for

| Family | Boundary shape | Strengths | Watch out for |
|---|---|---|---|
| Linear / logistic regression | straight | fast, explainable, robust with little data | needs scaled, well-behaved features; cannot bend |
| Decision tree | axis-aligned steps | readable, mixed types, no scaling | overfits alone |
| Gradient-boosted trees | flexible steps | strongest default on tabular; feature importances | many hyperparameters; overfits small data; less legible |
| k-nearest neighbours | local | trivial, no training | slow at scale; distance is scale-sensitive |
| Neural network | anything | text, images, huge data | needs lots of data; least explainable (Lesson 3.6) |

Start with logistic regression (or linear regression), move to boosted trees when the
boundary is clearly not linear, and reach for neural networks only for unstructured data.
In practice you will use scikit-learn or a boosting library; the mechanics above are what
those calls do.

## What a senior engineer should take from this

- **A model is a function from features to a score, fitted to labelled rows.** Regression →
  a number; classification → a score you threshold.
- **Feature code is shared between training and serving; statistics are fitted on training
  data only.**
- **Logistic regression first; boosted trees when it bends; neural nets for unstructured data.**
- **A score is not a decision. The threshold is a product choice.**
